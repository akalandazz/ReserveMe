# Запись в салон — Telegram Mini App

Мини-приложение для записи к мастеру. React + Vite. Контент салона хранится
в Supabase и правится прямо из приложения; заявки клиентов на сервер не уходят.

## Команды

```bash
npm install
npm run dev      # разработка, http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # посмотреть собранное
npm run lint     # oxlint
```

## Как поменять свои данные

Всё меняется **в самом приложении**, правки видны сразу, пересборка не нужна.

Откройте раздел «Настройки»:

- в Telegram — по ссылке `https://t.me/<бот>/<приложение>?startapp=admin`;
- в браузере — `http://localhost:5173/#admin`.

Войдите по e-mail и паролю мастера. После первого входа пункт «Настройки»
появляется в главном меню сам.

| Раздел | Что меняет |
|---|---|
| Услуги и цены | название, цена, длительность, описание, эмодзи, порядок, видимость |
| График работы | часы по дням недели, шаг сетки, горизонт записи, запас на сегодня, выходные, время суток для листа ожидания |
| Контакты и адрес | имя мастера, Telegram-логин, телефон, адрес, ссылка на карту |
| Важная информация | блоки текста на одноимённом экране |

⚠️ **Telegram-логин обязателен** — без него кнопки «Отправить заявку» не
работают и заявки клиентов до вас не дойдут. Рядом с полем есть кнопка
«Проверить ссылку».

⚠️ У существующих услуг **нельзя менять идентификатор** — по нему находятся
уже сохранённые записи клиентов, поэтому поле закрыто для правки. Если услуга
больше не нужна, **скрывайте её, а не удаляйте**: у скрытой услуги название
по-прежнему видно в старых заявках, у удалённой — нет.

Правка цены не меняет уже сохранённые заявки: в них записана та цена, о которой
договаривались.

## Первая настройка Supabase

1. Выполните [supabase/schema.sql](supabase/schema.sql) целиком в SQL Editor
   проекта — он создаёт четыре таблицы, политики доступа и начальные данные.
2. **Authentication → Users → Add user**: e-mail и пароль мастера, обязательно
   галка «Auto Confirm User».
3. **Authentication → Sign In / Providers → Email → выключите «Enable sign ups».**
   Это не опция: публичный ключ лежит в собранном приложении, и при открытой
   регистрации кто угодно сможет переписать ваш прайс и логин.
4. Скопируйте [.env.example](.env.example) в `.env` и впишите `VITE_SUPABASE_URL`
   и `VITE_SUPABASE_ANON_KEY` (Settings → API). Переменные подставляются при
   сборке, поэтому после правки `.env` нужен `npm run build`.

Ключ `anon` — публичный, он и должен уезжать в бандл. Данные защищает RLS
в базе. Ключ `service_role` в `.env` вписывать **нельзя**.

Раз в несколько месяцев имеет смысл сохранять дамп базы: контента больше нет
в репозитории, есть только схема и начальные значения.

## Как это работает

Заявки клиентов **не имеют сервера**. Когда клиент оформляет заявку:

1. Заявка сохраняется у клиента — в Telegram CloudStorage (привязано к его
   аккаунту, переживает переустановку), с запасным вариантом в localStorage.
2. Открывается чат с мастером с **уже набранным текстом** заявки, который
   клиент отправляет сам.

Подтверждение записи — только ответ мастера в чате. Supabase хранит контент
салона и ничего не знает о заявках.

## Ограничения

- Записи видны только клиенту. Мастер узнаёт о них **из сообщения в чате** —
  это единственный источник истины.
- Список свободного времени скрывает только **собственные** записи клиента.
  Это не общий календарь: двое разных клиентов могут запросить один слот.
- На клиентах Telegram старше версии 6.9 данные живут в localStorage WebView
  и могут быть очищены системой.
- Подстановка текста в чат (`t.me/<username>?text=…`) — поведение deep-link,
  а не документированный API мини-аппов. На некоторых клиентах может не
  сработать, поэтому рядом всегда есть кнопка «Скопировать текст».
- Первый запуск требует сети: контент приходит из Supabase. Дальше он берётся
  из кэша, и приложение открывается даже без связи.

## Развёртывание

Telegram принимает только **HTTPS**. Для проверки на телефоне:

```bash
npm run dev
npx localtunnel --port 5173   # или ngrok
```

Хост туннеля добавьте в `server.allowedHosts` в [vite.config.js](vite.config.js),
иначе Vite отклонит запрос. Полученный URL пропишите в BotFather:
`/newapp` → выбрать бота → указать ссылку.

Для продакшена соберите `npm run build` и выложите папку `dist/` на любой
статический хостинг с HTTPS.

## Структура

```
supabase/
  schema.sql     таблицы, политики доступа и начальные данные
src/
  content.js     контент салона: загрузка, кэш, правки из админки
  supabase.js    клиент Supabase и сессия мастера
  schedule.js    даты и свободные слоты (чистые функции)
  storage.js     заявки клиента: CloudStorage + localStorage
  telegram.js    обёртка над window.Telegram.WebApp + тексты сообщений
  ui.jsx         Screen / Row / Chip / Card / кнопки
  App.jsx        стек экранов и кнопка «назад»
  screens/       по файлу на пункт меню
    admin/       разделы «Настроек»
```
